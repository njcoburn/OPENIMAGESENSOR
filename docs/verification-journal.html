What the tests mean

There are three layers: physical layout checks, electrical behavior, and checks that the test software reports the right answer. Passing one layer does not replace the others.

1. Physical layout and circuit identity

2. Electrical behavior of the entire bank

A transient computes voltage changes over time. Our schedule captures a row and reads all 64 columns twice: 128 output samples over 3.98 ms of simulated time. The later scan checks the same captured data after additional storage time; it is not a second image exposure. Acquisition is 12 µs within each 20 µs readout slot.

Each case runs twice, with maximum timesteps of 100 ns and 50 ns. The 100 ns run also has 192 separately solved, matched-state references: 64 at capture and 128 at output. A reference freezes the relevant pixel/storage state and solves its settled response. This distinguishes capture/storage/readout errors from the voltage the same circuit would produce after settling. It is not a claim of absolute optical calibration.

CheckWhat is comparedAcceptance
Total capture/readout errorThe sampled output HOLD voltage versus the matched capture-state settled output for that column. Includes the combined effect of capture, storage and readout.Worst absolute difference < 500 µV (0.5 mV).
Output trackingThe sampled HOLD output versus a settled reference with that output sample's pixel/storage state frozen. Tests whether the output has settled sufficiently in the available slot.Worst absolute difference < 500 µV.
Saved-sample refinement100 ns versus 50 ns results at the same 128 sample instants, across every saved voltage, including internal nodes. The finer run has no additional DC references.Worst difference < 10 µV.
Physical-event refinementStorage-node voltage and physical MIM upper plate, lower plate and differential voltages around capture, row deselection and reset. This checks numerical agreement at those internal events.Worst 100/50 ns event difference < 10 µV. The size of a real switching excursion itself is not this acceptance metric.
Contrast orderAdjacent dark/bright samples have the expected voltage ordering: in this circuit, dark is higher than bright.Ordering must hold in both scans. Explicitly not applicable to uniform images; it is not a dynamic-range or noise test.
Parasitic-placement sensitivityMove the same conserved shunt-capacitance totals from their ports to recorded far nodes, then compare sampled HOLD and all 64 STORE voltages with the matching port-model baseline.Worst HOLD/STORE difference < 10 µV, plus the accuracy/refinement checks above. The completed experiment moves all 67 shunts jointly in two selected cases.

Five illumination patterns: all dark (0 pA/pixel), all middle (80 pA), all bright (240 pA), alternating dark/bright (0,240,…), and the inverse (240,0,…). Uniform patterns exercise common loading; alternating/inverse exercise neighboring contrast and both column parities. These are injected photocurrents, not specified lux levels. All five run at 27 °C and 125 °C. The present matrix uses typical transistor models, nominal extracted wire RC and a 3.3 V source with the existing supply/bias fixture.

Why it takes hours: each detailed extracted circuit requires many numerical solves, followed by independent references and audits. A four-transient/two-temperature batch recently took about 3.65–4.04 hours including audits. Six comparable batches for the current baseline plus selected placement would be roughly 24 hours on the same workstation, excluding rebuilds and troubleshooting. This is an estimate, not a measured full-suite runtime; new geometry and extra corners can take longer.

Definitions and implementation: transient/reference runner, independent bank auditor, placement auditor.

3. The test software and evidence

Regression tests verify sample timing, column selection, reference roles, the exact generated circuit decks, and compatibility with retained controls. Adversarial tests deliberately alter illumination, reuse evidence or placement data to ensure the auditor rejects it. Watcher/controller tests check that incomplete jobs, timeouts, measured failures and rendering failures cannot silently advance the sequence.

The uniform extension has 19 regression/adversarial tests; placement has 15; overnight continuation has five guard tests. These are software checks, separate from the 24 transistor-level transients in the current bank matrix. Existing full-bank control audits reproduced retained results before the new batches were launched.

An independent audit reconstructs decks, reads binary traces, checks reference completion, recomputes errors and records SHA-256 hashes. An integrity review checks that saved files still match those hashes. A clean container exit alone is insufficient: a completed audit can legitimately report an electrical failure. Visual plot review is recorded separately.

The repeatable workflow we need

Versioned design inputs→Physical build and checks→Small controls→Bank matrix→Placement and corners→Audit, compare, archive

A general layout-to-results command is not implemented yet. The individual tools exist, and the previous overnight controller can sequence one specific follow-on batch. It is tied to the current baseline. The catalogue now captures the current 12-case regression matrix, limits, tool image, report identities and history in machine-readable form.

  1. Freeze a revision manifest. Record the pixel source/parameters, independent schematic, pin/pitch contract, capture-column input, tool and PDK identities, model/corner choices, timing, accuracy requirements, and a unique run ID. Preserve older revisions.
  2. Build and verify fresh geometry. Pixel and boundary controls → joined tile → small bank → 64-column ground-grid bank. Run DRC/LVS, extraction/passivity checks, device census, clear-aperture and fit checks at the applicable stages. Retain raw and approximated extraction separately. A changed design needs its own geometry-change contract, not the old “ground additions only” assertion.
  3. Run quick software and electrical controls. Validate deck generation, pin/control schedules and small-circuit references before committing to long runs. A failure stops dependent work and produces a report.
  4. Schedule the bank matrix in bounded batches. Ten port-model cases, each with 100/50 ns transients and 192 references at 100 ns: 20 transients/1,920 references. Then two selected joint-far cases: four more transients/384 references. Placement baselines must come from the same new layout revision.
  5. Add the agreed remaining tests. Individual placements, local rail checks and the chosen corner matrix need explicit cases and exit criteria. They are not implicitly covered by the current catalogue. Avoid multiplying every dimension before selecting a justified staged matrix.
  6. Audit and publish per revision. Reconstruct decks, audit waveforms/references, compare with the previous design, hash evidence, render plots, and append a dated review. Record pass, fail, incomplete and not-applicable distinctly. Keep visual review separate from automated completion.

Controller work needed: replace fixed dated paths and global result filenames with manifest inputs and revision-specific outputs; remove the old-layout dependency from new auditor versions; parameterize process/supply consistently in the transient and reference builders; enforce resource limits, bounded retries and durable status. Restart must verify identities before reusing a fully completed stage. A partial SPICE transient is not resumable, and an expired watcher is not proof that its simulators stopped.

The intended user interaction is to select a pixel revision and test profile, start one command, then read one status report. The first implementation should reproduce the present known baseline before it is trusted with a changed pixel. Existing pinned runners/auditors remain intact as controls.
